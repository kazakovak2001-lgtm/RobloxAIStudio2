## Architecture

### Job Lifecycle State Machine

```
QUEUED → VALIDATING → PLANNING → EXECUTING → EVALUATING → GENERATING_ARTIFACTS → COMPLETED
     ↓         ↓          ↓          ↓            ↓                ↓
  CANCELLED  FAILED     FAILED     FAILED       FAILED           FAILED
  TIMEOUT    CANCELLED  CANCELLED  CANCELLED    CANCELLED        CANCELLED
             TIMEOUT    TIMEOUT    TIMEOUT      TIMEOUT          TIMEOUT
```

Retry: FAILED/TIMEOUT → QUEUED (if retryCount < maxRetries, and failure is not deterministic)

### Integration with Existing Systems

- **RuntimeExecutionController** (v1.8) — wrapped by JobManager for full pipeline execution
- **PlanExecutor** — called within RuntimeExecutionController, unchanged
- **AgentRegistry** — passed to RuntimeExecutionController, unchanged
- **No public API changes** — existing routes preserved

## Key Design Decisions

1. **Jobs are not API routes** — the engine is a service layer. Routes can call `JobManager.submit()` without changing API contracts.
2. **Retry policy excludes validation failures** — deterministic failures (missing intent, schema violations) are never retried.
3. **RuntimeExecutionController is the execution backend** — JobManager delegates to it, preserving the v1.8 checkpoint/telemetry/error-boundary stack.
4. **Queue rejects invalid jobs before enqueue** — fail-fast at submission time.
5. **State machine is strict** — no invalid transitions allowed (throws on attempt).

---

## Known Limitations

1. Job state is in-memory only — restart loses all job data (persistence recommended for v2.1)
2. Queue metrics reset on restart
3. No webhook/callback notification on job completion
4. Scheduler poll interval (100ms) may need tuning under load

---

## Recommendations for v2.1

1. **Persist job state** — write to EventStore or file system for durability
2. **Wire JobManager into API routes** — expose `/api/v1/jobs/submit`, `/api/v1/jobs/:id/status`
3. **WebSocket job progress streaming** — push progress events to frontend
4. **Webhook notifications** — notify external systems on job completion
5. **Priority aging** — prevent low-priority jobs from starvation
