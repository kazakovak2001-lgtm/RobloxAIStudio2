## New Runtime Layer (`server/src/runtime/`)

### 1. RuntimeExecutionController

**Path:** `runtime/controller/RuntimeExecutionController.ts`

Explicit lifecycle state machine:

```
INIT → PLANNING → EXECUTING → VALIDATING → FINALIZING → COMPLETE | FAILED
```

Features:

- Phase transitions with telemetry emission at each step
- Checkpoint creation per phase (resume-capable)
- Error boundary wrapping all agent calls
- Timeout enforcement per agent (60s default)
- Resume-from-checkpoint capability

### 2. ExecutionCheckpointSystem

**Path:** `runtime/checkpoint/ExecutionCheckpointSystem.ts`

- Snapshot every pipeline phase
- Deep-clone state (JSON parse/stringify)
- Per-execution retrieval (latest, by-phase)
- Export to JSON for debugging
- Max 20 checkpoints per execution (auto-evict oldest)

### 3. RuntimeErrorBoundary

**Path:** `runtime/errors/RuntimeErrorBoundary.ts`

Catches ALL errors — no silent failures:

- Agent crashes → `ExecutionFailureReport`
- Null/undefined output → captured and reported
- Non-JSON output → captured and reported
- Timeouts → detected via Promise.race
- Every failure has: `failureType`, `phase`, `message`, `timestamp`, `recoverable`

### 4. PipelineTelemetry

**Path:** `runtime/telemetry/PipelineTelemetry.ts`

Structured telemetry:

- Per-execution tracking (start, phases, completion)
- Agent call counter
- Phase timing metrics
- Event log (structured JSON)
- Aggregate metrics (success rate, avg duration)
- Export to JSON

### 5. E2EGenerationSimulator

**Path:** `runtime/simulation/E2EGenerationSimulator.ts`

End-to-end validation harness:

- Runs full pipeline (mock or real mode)
- 7 validation checks:
  1. Execution completed (not stuck)
  2. Outputs exist
  3. Outputs are JSON-valid
  4. Checkpoints were created
  5. No silent failures
  6. Telemetry captured
  7. Agent calls tracked
- Batch mode with success rate computation

### 6. FailureModeRegistry

**Path:** `runtime/failures/FailureModeRegistry.ts`

12 pre-defined failure modes across 3 categories:

| Category      | Modes                                                            |
| ------------- | ---------------------------------------------------------------- |
| Deterministic | schema-mismatch, missing-input, invalid-config, non-json-output  |
| Probabilistic | agent-inconsistency, llm-hallucination, quality-drift, low-score |
| System        | timeout, deadlock, oom-estimate, network-failure                 |

Each mode defines:

- Severity (low/medium/high/critical)
- Recovery strategy (retry/fallback/skip/abort/checkpoint-resume/manual)
- Max retries
- Escalation policy
- Detection signal

## How to Use

```typescript
import { RuntimeExecutionController } from "./runtime";

const controller = new RuntimeExecutionController(agentRegistry);
const result = await controller.execute({
  executionId: "exec-001",
  intent: "Generate an obby game with 10 levels",
  constraints: ["kid-friendly", "no monetization"],
  projectId: "my-project",
});

// Resume from checkpoint on failure:
const resumed = await controller.execute({
  executionId: "exec-001-retry",
  intent: "Generate an obby game with 10 levels",
  constraints: ["kid-friendly"],
  resumeFromCheckpoint: result.checkpoints[result.checkpoints.length - 1],
});
```
